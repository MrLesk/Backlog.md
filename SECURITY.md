# Security policy

## Repository trust

Backlog.md trusts the files in the checkout you use. This includes the project
settings, task files, and any commands they configure, such as status hooks or an
external editor. This applies to people and agents alike. Use Backlog in
checkouts you trust, including the branch or fork on disk.

Repository owners control who can push and what gets merged through Git and
their hosting service. Backlog manages project tasks. Use your operating system,
firewall, and antivirus to protect your machine, and use Git hosting controls
and review to protect your repository.

The live browser listens on the local machine by default. If you make it
reachable from other devices, use your network controls to limit who can view
and change project data.

## Report a vulnerability

Use GitHub's [private vulnerability report](https://github.com/MrLesk/Backlog.md/security/advisories/new)
for a suspected security issue in Backlog. Include the affected Backlog version,
the operating system, what access or user action is needed, and what harm can
result. If possible, check the [latest release](https://github.com/MrLesk/Backlog.md/releases/latest).
Keep sensitive details in the private report.
